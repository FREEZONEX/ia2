# 工程状态观测：位置模式与证据

2026-11-16，UTC+8。此版本交付只读观测闭环，帮助工程师和 agent 先查可读事实，再判断缺少的现场信息。

设备编辑器的 EtherCAT 页面新增 **Engineering state**。选从站后点击 **Refresh device observation**，通过当前运行器的既有主站读参数；结果与 CLI、API 使用同一个观测编号、解释和持久记录。查看历史不访问总线。停止状态不会暗中启动服务。

## 可以回答的问题

| 现象 / 证据 | 共同解释 |
|---|---|
| SV660N H02-01 = 0 | 增量模式；报告坐标不能跨驱动断电比较，外接电池不会自动启用绝对模式 |
| H02-01 = 1、2、3 | 绝对模式已配置；实际生效、保持能力和机械原点仍需验证 |
| H02-01 = 4 | 单圈绝对值；不能作为多圈机械位置保持证据 |
| 编码器故障信息非零 | 保留故障信息，不能确认绝对参考；不自动复位或清多圈 |
| 读取失败 / 协议不支持 | 对应项未知，附原始错误；不填零、不继承旧值冒充当前 |
| 序列号为零 | 只能识别观测槽位与型号，无法证明跨重连仍是同一实体设备 |
| 批内身份不同 | 本批位置解释未知，保留逐项身份，禁止合并解释 |

所有记录都明确是采样时点的证据。页面可选择过去的记录，并列查看上一记录的数值；比较不证明机械运动、坐标连续性或参数一直未变。已编辑但未保存的设备配置不作为读数来源。刷新只按已保存目标名定位实际运行对象，不宣称磁盘配置等于运行器已加载的配置。

## 读取范围与厂家依据

共享实现位于 `ironplc-bridge::monitor::engineering`。标准对象为
`6041:00`、`603F:00`、`6064:00`、`6061:00`。只有读回身份的 vendor
`0x00100000`、product `0x000C010D` 匹配时，才使用 SV660N profile：

- `2002:02` 绝对系统模式、`2000:01` 电机代码、`2002:03` 方向；
- `200B:1D` 编码器故障、`6091:01/02` 电子齿轮、`607C:00` 原点偏移；
- `2005:2F/31` 线性偏移、`200B:47/48` 多圈和单圈字；
- `200B:4E/50` 绝对位置高低字。

依据：[Inovance SV660N Advanced User Guide](https://www.inovance.eu/fileadmin/downloads/Servo_drives_and_motors/SV660N_Advanced_User_Guide.pdf)，§7.11，印刷页 302–311 及对象字典。H02-01 为 Uint16，需下一次上电生效；14101 对应 23 位绝对编码器。不同固件是否支持这些对象仍以逐项实际回复为准。

高低字只展示原始值，不拼成可信的运动中 64 位位置。数值类型和字节数分别校验；位置使用驱动参考单位，不自动换算机械距离。其他设备仅返回标准读取及未知保持能力，不套用 SV660N 电池规则。

## 使用与存储

```bash
cs --project demo get runtime/engineering-state
printf '%s' '{"device":"bus","slave":1}' | cs --project demo api POST /api/runtime/engineering-state/refresh --from -
cs --project demo get edges/edge-a/engineering-state
```

见 [HTTP 契约](api.md#engineering-state-observations)。返回中的 `saved` 与逐项读取结果分别判断；200 不等于全部成功。一个服务同时只接受一批刷新，每个上传等待最多 500 ms，读取总预算 2.5 s。超预算项目保留为超时。磁盘操作不在 PLC 扫描线程执行。

本地路径为工程 `state/engineering/observations.json`；edge 路径为
`--state-dir/engineering/observations.json`，跨部署版本保留。每次原子替换保存
最新 64 次观测，按提交顺序而非墙钟排列，最大 4 MiB。锁阻止跨进程并发覆盖。
损坏或未知版本的存档不会自动覆盖。落盘失败返回已读证据及保存错误；客户端
应自行保存必要证据。日志容量有限，重要验收记录须另行归档。

边缘服务停机时其 HTTP 历史暂不可达；已经导出的 JSON 可离线查阅，仍属历史。
本地证据不进入部署包。RETAIN 冷启动只处理 `retain.json`，不能顺带删除工程证据。

## Agent 如何避免重复询问

1. 先读历史及当前作业记录，引用观测编号、原始回复、时间与适用范围。
2. 用显式刷新核对可读项。增量模式解释的是坐标连续性限制，不证明机械位置移动，也不证明电池坏了。
3. 现场确认、动作授权、机械参考、实时联锁分别判断。聊天更换、进程重启或工具重连本身不是重新询问机械接线的理由；沿用仍适用的事实。
4. 只对当前动作必需且真正缺失或矛盾的事实合并补问。静止漂移观察可使用新观测区间；依赖旧机械坐标、软限位或累计行程的运动仍需有效坐标关系。
5. 不自动把历史位置加回当前零点，不重置累计行程预算，不因绝对模式配置而自动恢复运动。

此版本提供这些判断所需的设备证据，不代替现场确认档案、权限系统或运动联锁。

## 实现边界与后续维护

尚未交付：正式停机 PRE-OP 诊断会话、可配置参数关注项、加载工程指纹与总线代次、坐标标定及版本、保持验收事务、跨重连有效性恢复、现场事实与动作授权档案、永久审计及导出包管理。因此 `mechanical_reference`、`bus_continuity` 始终为 `not_verified`，没有“已确认绝对机械坐标”的自动判定。

后续首先在协议层增加总线代次和实际工程身份，再实现有证据的机械坐标与验收状态；不能把 PID 当作机械坐标版本，也不能仅靠历史坐标恢复掉电参考。停机诊断必须沿用原服务独占主站，禁止下载、PDO 周期启动和 OP，保留部分读取与退出证据。相关完整设计见[设备参数状态设计](field-state-design.md)。

回归包括多个位置模式、另一厂商、未知身份、宽度错误、超时、编码器故障、损坏存档、并发、容量、重启持久性、多工程隔离、页面切换迟到响应，以及 `engineering_observation.toml` 的零输出场景。模拟 SDO 返回不支持，不伪装现场读数。实际电池保持、固件兼容性及机械坐标恢复仍须独立现场验收。
