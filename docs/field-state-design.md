# IA2 设备参数状态与变更追踪设计

状态：设计草案。下述 IA2 参数观测与归档能力待实现。2026-11-09，UTC+8。

IA2 应内建设备参数的读取、状态判断、变更追踪与证据引用能力。用户、HMI、CLI 和外部 agent 查询同一个设备参数时，应得到同一组有身份、有时间、有来源的结果；历史分析中的数值不能被默认为当前现场值。记录的存储位置、导出和恢复由 IA2 管理，用户无需维护“现值文件”或依赖某个聊天持续记忆。

## 用户可见行为

以某参数先读回 0.15、后来读回 0.30 为例：

| 场景 | IA2 应给出的结果 |
|---|---|
| 新读回成功 | 显示 0.30、设备身份、主站读取时间和观测编号，并分别显示记录保存结果；此前 0.15 可按编号查阅 |
| 查询历史分析 | 明确其引用的观测编号；相关参数已经变化时标为“依据已变化，需重新验证” |
| 当前读取失败 | 明确报出失败原因；0.30 只能显示为“最后成功读回”，不能充当本次读取结果 |
| 服务重启或通信重连 | 保留历史；在新会话重新核实前，旧观测不能标成新会话的已确认读数 |
| 同一总线位置更换设备 | 显示身份变化，旧设备记录不能归到新设备名下 |
| 多个客户端同时查看 | 返回同源记录；较晚到达的旧响应不能覆盖较新的观测 |
| 基于旧观测发起受控改参 | 服务端核对实际旧值和适用上下文；前提不成立时拒绝，不按旧分析自动恢复参数 |
| 导出或离线查看 | 已导出的证据包保留观测编号、时间、身份和证据引用，标为历史；停机且尚未取回的远端记录显示暂不可达 |

“已观测”只表示该时刻读到了这个值，不表示参数此后持续不变。驱动设定的惯量比与机械系统辨识出的真实惯量比是不同事实，必须使用不同的数据类型和来源。

## 三类数据

- **期望配置**：工程要求的值、数据类型、单位和允许范围。修改期望配置不构成现场写入，也不把它标为已生效。
- **现场观测**：由 IA2 的实际读取生成，包含原始字节、设备身份、采样时间和读取结果。客户端不能把聊天或手工填写的数值提交成设备回读。
- **分析依据**：某项分析引用的观测编号及依赖参数。依赖变化时提示重新验证；原分析和原始记录保留，不改写成新参数下的结论。

现场人员确认、操作授权与设备观测分别表达。参数读回成功不代表现场人员在场，也不扩大动作授权。

## 首版完整范围

首版交付 EtherCAT 标量 SDO 只读闭环。用户声明关注参数，显式请求刷新，按编号查看和比较可靠保存的读数，并可在停机后离线查看已导出的证据包。HTTP、现有 CLI 和设备或监视界面使用同一观测编号与状态。协议不支持、主站未运行或读取失败时，返回具体原因并保留最后成功记录。

参数描述扩展现有设备配置，包含对象地址、类型、可选单位换算和依据。描述缺失时返回原始字节、宽度和地址。零序列号或其他弱身份只支持相应总线会话内的槽位和型号识别。参数关注项与既有 PRE-OP `init_sdo` 配置分别建模，关注项的编辑只改变观测范围和解释。

比较请求可携带分析依赖的观测编号及上下文，响应逐项给出差异或未知原因。首版保存观测，分析原文由其来源管理。台架作业记录用观测编号、来源及适用范围引用 IA2 证据，分别保存工程配置核对、实时联锁、现场确认和动作授权。现场确认包含适用作业、原文及来源。执行进度和一次动作的消费独立记录。作业已完成或现场连接中断时，档案继续展示最后读数，实时状态另行核对。

首版采用按请求刷新。参数写入与现场作业准入属于独立能力。后续接入的维护事务统一引用观测并遵循下文的事务契约。

## 统一数据契约

每条观测至少包含以下信息。正式字段名和 HTTP 路径在实现时统一进入 `docs/api.md`，本设计中的名称不是已经可调用的接口。

| 信息 | 作用 |
|---|---|
| 安装实例、工程和设备身份 | 由实际运行对象绑定已加载工程指纹、总线地址和设备身份保证范围，避免同名工程和换机记录混用 |
| 运行实例和总线会话代次 | 读取前绑定实际运行对象和主站会话，返回前核对代次。重启、切工程或重连后，旧结果只可归档 |
| 参数键、协议地址、原始字节 | 明确读取对象，保留可重新解释的原始数据 |
| 类型、单位、换算与描述版本 | 避免 raw 15、0.15 和 15 倍混用；描述变化可追溯 |
| 主站读取时间、接收时间 | 记录主站读请求区间及读回时间。设备自身采样时点未知时留空 |
| 观测编号与顺序 | 按受理顺序标识最近尝试，按同会话内的实际采集顺序选择最后读数，按日志提交顺序分页及恢复 |
| 读取结果和原始错误分类 | 区分成功、忙、超时、不支持、身份不匹配和不可达 |
| 原始证据引用与持久化结果 | 区分“设备已读到”与“记录已可靠保存” |

最近读取尝试、最后成功读回与最后可靠保存的观测分别表达。一次超时只更新该次尝试。落盘失败时可返回本次读到的值和保存错误，重启后可恢复的最后观测仍以可靠保存的记录为准。HTTP 到达时间和墙钟仅用于展示，顺序由采集端和日志分别确定。

一组顺序读取具有自己的编号、开始和结束时间，并保留每项采样时间与结果。分别报告覆盖范围、会话是否连续以及比较结果。每项成功只证明各自时点的读数，多项同时一致性保持未验证。缺项、超时、身份或描述不可比的项目明确标记未知。会话变化时终止该批，保留已取得的部分证据。

分析只检查它声明依赖的参数和上下文。参数恢复同值时，新的观测可重新匹配数值，历史变更和其他分析前提仍单独判断。依赖证据缺失时返回“无法确认”。

## 状态与刷新规则

记录查询与导出采用只读查询语义。显式刷新另走受限的诊断请求，响应注明此次是否访问设备、是否读到、是否保存。现有即时 SDO 诊断接口保留兼容语义。按编号查阅使用已记录观测资源。

会话内的新鲜度以单调时间计算，阈值由参数性质和操作约束决定。主站健康、扫描推进和历史文件时间均独立于参数新鲜度。部署和磁盘文件核对独立于已加载工程身份。缓存的连接拓扑只作为历史证据，当前拓扑需要本总线会话内的发布证据。

设备面板、厂家软件等外部写入可能不经过 IA2。IA2 只能在实际读取时发现当时可见的差异，两个读回之间发生又恢复的变化可能不可见。IA2 修订号约束自身管理的请求，外部写入仍以设备读回为依据。

读取使用现有主站的受限邮箱通道。主站或工程停机时，显式刷新返回不可达。刷新在请求进入扫描命令队列前限制并发、请求规模和等待预算，邮箱仍按通信容量及当前条件运行。繁忙时返回原因或进入有界队列。

## 受控写入如何接入

受控写入引用预期观测和目标值，由 IA2 串行核对设备身份、上下文、实际旧值、权限及联锁，再执行既有支持范围内的写入，随后独立回读。

服务端在下发前持久登记动作 ID、请求内容、授权范围和写入意图。同 ID 同内容的重送返回既有事务状态，内容冲突时拒绝。记录区分确定未发、可能已发、协议确认、独立回读和最终状态。超时、断线或重启后遇到结果未知，先查记录并只读核验。此时读到目标值只证明新观测，原事务归因仍待证据。后续恢复动作使用其自身的授权和动作 ID。

即时回读与断电保存分别表达。写入响应或即时回读成功，不能被描述为已经写入非易失存储。操作记录的持久性也不等于驱动参数的断电持久性。

## 实现落点

共享语义放在现有 `ironplc-bridge` monitor 层，server 和 edge runtime 使用同一实现；协议适配器提供实际读取与身份，HTTP、CLI 和 HMI 都作为客户端。沿用 API-first 和现有 `cs ls/get/set/rm`、`cs api`，不增加一组专用命令。

运行实例负责在配置的持久状态目录保存版本化追加记录，并从中生成最后观测视图。证据目录须跨程序升级、重启和回滚保留，并与 RETAIN 冷启动清理隔离。加载旧记录时标为历史。离线查看使用已导出的证据包。运行时停机且远端记录尚未导出时，明确标记暂不可达。工程机与 edge 使用同一证据契约。

持久化由非实时线程的单写者处理，队列有界且故障可见。“证据已保存”要求记录经过持久提交，能在进程崩溃或服务重启后恢复。存储层支持掉电恢复时，单独声明并验证该保证。恢复时保留并报告损坏尾记录及缺失区间。要求可恢复证据的维护事务在日志不可用时拒绝开始，中途失去记录能力则报告已知阶段。PLC 扫描与周期 PDO 独立于磁盘等待。

历史查询需要分页、容量上限和明确保留策略。清理不能改变“最新观测”的语义；已导出的观测编号继续指向其归档证据。暂不要求外部数据库、独立同步服务或 agent 专属存储。

## 验收条件

| 编号 | 必须证明的行为 |
|---|---|
| A1 | 先读 0.15 后读 0.30：所有客户端均显示后者及其时间，旧记录仍可按编号查询 |
| A2 | 0.30 后读取超时：本次明确失败，历史 0.30 只能作为最后成功读回展示 |
| A3 | runtime 重启、总线重连、换设备或同型号同槽位且 `serial=0`：保留历史，旧会话结果和弱身份明确标注 |
| A4 | 并发请求、迟到响应、墙钟回拨：最新视图和历史排序不会被旧数据覆盖 |
| A5 | 依赖参数经历 0.15→0.30→0.15：展示观测差异与返回同值，依赖缺失报告未知，无关扫描推进不触发失效 |
| A7 | 持久化失败、磁盘满、崩溃恢复及损坏尾记录：不假报保存成功，不静默丢弃唯一证据，扫描不等待磁盘 |
| A8 | 单位描述缺失、描述版本变化、64 位整数：原始字节完整，未确认的换算不冒充工程值 |
| A9 | 多项顺序读取全成功、部分失败或中途换会话：分别显示覆盖、采样区间、会话连续性及可比较项目 |
| A10 | HTTP、CLI、界面、导出和恢复使用同一编号及状态。停机时可读已导出的证据包，未取回的远端记录显示暂不可达，主站和工程维持停机 |
| A11 | 请求洪峰、邮箱忙或慢盘：入口维持有界，返回可辨识结果，周期 PDO 和扫描无需等待持久化 |

受控写入接入门槛 A6 单独验收。旧值不符、写入意图无法持久保存时，实际下载次数为零。同动作 ID 并发或跨重启重送复用原状态，同 ID 内容不同则拒绝。下发后结果未知时，仅查历史和独立回读，下载次数保持原样。

软件验证使用明确标注的仿真/测试设备和故障注入。现有 `_sim` 不支持真实 SDO 的行为不得变成虚构现场读数。行为变化遵循项目要求补充仿真场景和必要的集成测试；现场验收在独立授权的作业中完成。

[设计评审与回归用例](field-state-regression.md)列出合成输入、操作顺序和应保留的证据。

## 与现有能力的关系

现有主线只读 SDO 已返回原始字节、设备身份和主站生成响应时的墙钟时间，可作为观测来源。首版还需补齐已加载工程和总线会话身份、采集序号及持久回执。变量 historian 负责运行趋势，现有 `/audit` 是有界内存环。参数证据的跨重启恢复采用独立的保存契约。

本设计沿用 [API 契约](api.md)、[edge 持久状态布局](edge-deploy.md#layout-on-the-edge) 和 [项目设计原则](../MEMORY/principles.md)。主线 SDO 能力已核对至 `5ae1cc7da3d6d503e5c555512121e64a63fd8831`。新增资源、存储和界面均待实现。
